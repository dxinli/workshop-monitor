config 源码结构图

config 的作用是「载入 → 校验 → 投影」。 它把 config/ 下的点表、阈值、主题模板读成结构体，用 V-01~V-12 逐条判合格， 再投影成 02_seed.sql 交给 psql。全部判定在文件里完成，不碰数据库。

依赖边界

这个包之所以能被边缘侧和平台侧同时引用，靠的是它不反过来依赖任何一方。

In

只吃配置文件

输入全部来自 config/ 目录：terminals/*.json、thresholds.json、topics.json、adapter.json。配置文件是唯一权威源，数据库只是供界面读取的投影。

Deps

只依赖标准库

encoding/json、fmt、io、os、path/filepath、regexp、sort、strconv、strings。workshop-monitor/ 下的包一个都不 import——它是共享层的前提。

Out

被边缘侧与装配层共用

8 个文件 import 它：internal/agent 3 个（poller · codec · uplink），cmd/ 5 个（三个 main 加 serial、settings）。agent 只消费结构体，载入与校验发生在 cmd/ 装配时。internal/adapter 一个都不 import——平台侧只在 cmd/proto-adapter 读一次 LoadAdapter 与 LoadTopics。
