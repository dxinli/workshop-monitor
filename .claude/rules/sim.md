# 仿真件

三个 Python 仿真件：`modbus-slave-sim`（替代 50 台传感器）、`bypass-sim`（替代多终端与 30 天历史）、`wecom-mock`（替代企业微信接收端）。

不属于产品交付范围。真实现场具备硬件后本目录整体失效，产品需求继续有效。

## 隔离

- `sim/` 不 import `internal/`。模型定义各自维护，用 `../docs/02-设计/04-接口规范.md` 的契约文本对齐，不共享代码。
- `cmd/` 不 import `sim/`。
- 仿真件不进交付镜像，交付镜像只含两个 Go 二进制。
- 删掉 `sim/` 后 `make build` 仍须通过。

一旦产生 import，仿真件就成了交付依赖，客户现场无法移除。

## 验证通道

| 通道 | 路径 | 能证明 | 不能证明 |
|---|---|---|---|
| 主通道 | 模拟器 → 虚拟串口 → 采集应用 → Broker → 平台 | 从现场接口读到平台展示的完整链路 | — |
| 辅助通道 | 旁路构造器 → Broker → 平台 | 接入、存储、告警、界面 | **不能证明能读 RS485** |

涉及采集能力与缓存补传的验收（AC-01~03、AC-09~13、AC-16）**必须走主通道**。辅助通道不得用于证明采集能力，也不得替代缓存补传验证。

辅助通道能轻松造出"平台上数据很好看"的假象，但它完全绕过采集环节。允许它参与验收，被验证的将是界面渲染而不是从设备读数。

## 从站模拟器

| 项 | 要求 |
|---|---|
| 规模 | 10 条独立总线，每线 5 台共 50 从站，地址 1~5 可配 |
| 测点 | 按设备与测点模型 §3 模拟全部 140 个寄存器 |
| 改值 | 运行时修改任意寄存器，一个采集周期内体现 |
| 停启 | 暂停 / 恢复指定从站响应，触发设备离线与恢复 |
| 异常 | 注入超时、异常码、校验错误 |
| 串口 | 虚拟串口接入，参数可配，多总线并行 |
| 波动 | 模拟量自动波动与越限概率可配 |
| 工况 | 批量预设正常 / 告警 / 安全事件 |

异常注入必须是**协议层真实异常**（超时、异常码 0x83/0x84、CRC 错），不是返回错误值。返回错误值验证的是应用层容错，不是通信容错。

控制接口按接口规范 §12.1 的路径式接口实现，走 `127.0.0.1:8080`，不对公网暴露。
路径里的总线键是 `{terminalId}/{busId}`：`busId` 只有 `A` / `B`，不带终端时 10 条总线会塌缩成 2 条。

## 旁路构造器

- 可配置生成 N 台虚拟终端，数据隔离、标识正确
- 数值支持随机波动与越限概率
- 支持按时间正序生成近 30 天历史
- 报文必须与接口规范 §5 上行契约**逐字段一致**，含 `seq`、`collectTime`、`backfill`、`quality`
- 一律使用 `quality=7 (SIMULATED)`，终端标识用 `bypass-*` 前缀

字段有任何差异，验收结论就不可信。仅用于演示与界面数据准备。

## 通知接收端

- 提供可访问的接收地址
- 按企业微信机器人消息风格渲染卡片，含车间、终端、测点、级别、触发值、发生时间、告警原因
- 保留投递记录，可按时间倒序查询
- 不改写 `notifyId`

## 部署

模拟器最终走 Compose `sim` profile，与 `core` 分开启动；单实例常驻内存 ≤ 100 MB。
004 交付的是宿主机 venv 形态（`sim/modbus-slave-sim/README.md`），Compose 服务
与镜像随首次需要容器化的任务补齐，偏差登记在 `tasks/004-仿真链路与点表核对.md`。

```bash
scripts/setup-pty.sh                       # 生成 10 对 pty 与端点表
.venv/bin/python sim/modbus-slave-sim/main.py \
  --config config/terminals --ports .pty/ports.json
curl -X PUT localhost:8080/api/v1/reg/ESN-ZX-0001/A/1/0 \
  -H 'Content-Type: application/json' -d '{"value":625}'
```
