## 偏差

1. **确认不改 `alarm.status`。** 任务单原文要求「告警状态转 `ACKED`」，但状态机是
   `ACTIVE → RECOVERED → ACKED`，现场常常在告警还 ACTIVE 时就确认。此时改 status 会让
   010 的 `Clear`（只更新 `ACTIVE` 行）再也写不进真实恢复时间，且 `ux_alarm_active`
   只覆盖 ACTIVE 行，同键下次告警会另起一行把历史切两段。已实测 `UPDATE` 影响 0 行。
   裁决为**确认只写 `alarm_ack`**，登记 O-18。

2. **引入 `@flowfuse/node-red-dashboard` 1.34.1。** 官方镜像不带任何 contrib 节点，
   架构文档 C11 要求 Node-RED Dashboard 承担写视图。版本锁 `deploy/versions.env`，
   与「版本一律锁补丁号」一致。新增第三方依赖，已同步 `AGENTS.md` 依赖清单。

3. **补全模拟器的工况预设。** 004 偏差第 3 条把 `/api/v1/scene/{name}` 与
   `config/scenes.json` 推给后续任务，N-04 的「场景切换」按钮依赖它。本次一并交付：
   预设按**测点编码**声明工程值，不按寄存器地址——点表改（V-06/V-07）时场景不该跟着改。

4. **`normal` 不复位 `ep_forward`。** 累计电能写回小值等于让电表倒转，真实设备上不可能
   发生，场景里也不该假装能复位。其余 13 类测点全部复位。

5. **场景接口路径不带终端维度。** 接口规范 §12.1 原文如此，语义也对：「让 5 台终端一起
   进入报警工况」才是演示要的。要单点改写走 `/api/v1/reg/...` 那一族。

6. **N-03 走 `workshop_dashboard` 连接。** 与 N-01/N-02 的 `workshop_notify` 分开：
   「发通知」与「改告警」必须是两个权限，混用一个角色等于把通知侧的权限放大到能改告警。

7. **配置域只读由数据库权限兜底，流程里不写判断。** 写视图对 `threshold` / `point`
   没有 UPDATE 权限，改点在配置文件 + 重启，热加载由 010 的 `ReloadLoop` 承担，
   本任务不重复实现一份。

8. **`SELF_URL` / `SIM_URL` / `GRAFANA_URL` 走环境变量。** 模拟器跑在宿主机（004 交付的
   是宿主机 venv 形态，见 O-13），容器里的 `127.0.0.1` 不是它，compose 加了
   `host.docker.internal:host-gateway` 映射。地址写死在流程里换环境就失效。

9. **验收里的场景按钮用 inject 触发。** 按钮是 UI 事件，脚本点不动；`verify-ack.sh`
   在**临时目录**给三个场景函数各补一个 inject 节点，打的是同一条
   「函数 → http request → 模拟器」链路。仓库里的 `flows.json` 不含这些节点。
