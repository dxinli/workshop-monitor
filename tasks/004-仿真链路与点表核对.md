# 004 仿真链路与点表核对

> 计划任务：M4（复杂度 L）　状态：已完成
> 仿真形态下执行，见「偏差」

## 要建什么

把"从寄存器读到工程值"这条物理链路搭起来并证明可读：

1. `sim/modbus-slave-sim` — Modbus RTU 从站模拟器（Python + pymodbus），响应 10 总线 × 5 从站 × 140 测点
2. `scripts/setup-pty.sh` — 生成 pty 端点对并写入 `.env`
3. 点表核对记录 — 逐点读取的对照表

原计划假设现场硬件。仿真形态下**模拟器是本任务的必要交付**，否则 140 点无从核对。

## 验收

- [x] 模拟器启动后 10 条总线各自独立，从站地址 1~5 不串号
- [x] 逐点读取 140 个测点，寄存器地址与点表一一对应
- [x] 运行时 `PUT /api/v1/reg/{terminalId}/{busId}/{slaveAddr}/{addr}` 改值，下一周期读到新值
- [x] 能注入三类异常：超时、异常码（0x83/0x84）、CRC 错
- [x] 点表核对记录落盘 140 行：终端 / 总线 / 从站 / 寄存器地址 / 类型 / 缩放 / 读回值
- [x] `sim/` 不 import `internal/`，`cmd/` 不 import `sim/`

## 偏差

原 M4 依赖真实 RS485 与现场仪表。仿真形态改为虚拟串口 + 从站模拟器，验收口径从"与现场仪表读数一致"改为"与模拟器寄存器值一致"。

物理电气特性（终端电阻、信号反射、总线负载）不在范围，见 `../../docs/05-部署与运维/04-仿真验证环境说明.md` §3。

1. **控制接口路径带终端段。** 任务单与 `rules/sim.md` 原文写 `POST /api/registers`，接口规范 §12.1 写
   `PUT /api/v1/reg/{busId}/{slaveAddr}/{addr}`。两种写法都缺终端维度，而 `busId` 只有 A / B，
   10 条总线跨 5 台终端，仅凭 `busId` 无法定位——改一台终端的 A 总线会同时改掉另外 4 台。
   本任务统一为 `PUT /api/v1/reg/{terminalId}/{busId}/{slaveAddr}/{addr}`，并把接口规范 §12.1、
   `rules/sim.md`、本任务单验收措辞一并改齐；`rules/sim.md` 仍要求"协议层真实异常"，未变。
   登记为 O-12。
2. **本任务交付宿主机 venv 形态，不起 Compose `sim` profile。** 任务单交付清单只有模拟器、
   pty 脚本与核对记录三项；现有 `deploy/docker-compose.yml` 没有 sim 服务，镜像与 Compose 定义
   属于部署范畴。`rules/sim.md` §部署的目标形态（Compose profile、镜像 ≤ 3 GB）保留不变，
   随首次需要容器化的任务补齐。登记为 O-13。
3. **`/api/v1/scene/{name}`、`config/scenes.json`、模拟量自动波动与越限概率未实现。**
   这三项在 `rules/sim.md` 的从站模拟器要求表里，但不在本任务单六条验收内，属 011 / 016 的
   演示与试运行需要（工况预设是通知链路验收的前置）。按 Spec 轴不做预判式实现。
4. **异常码只实现 01~04。** 接口规范 §3.6 只要求「异常码细分 01/02/03/04 记入 detail」；
   0x83 是 FC03 异常响应的功能码字节，0x84 是 FC04 的，二者不是异常码。验收脚本分别用
   FC03 与 FC04 请求各取一次，确认两个功能码字节都能真实出现。
5. **验收脚本自带一个最小 RTU 主站。** pymodbus 客户端把 CRC 错与超时折叠成同一种异常，
   而本任务要区分的正是这两类，因此核对工具直接按帧收发并按 CRC 判定。
   从站侧仍由 pymodbus 承担，`rtu.py` 只补它不提供的两个动作（异常帧、CRC 破坏）。
6. **核对记录的期望值来自哨兵写入，不来自模拟器初值。** 每个测点先写一个全局唯一的哨兵原始值
   （`1000 + 序号 × 13`）再逐点读回；地址错位、总线串号、拆字顺序错都会让读回值对不上。
   直接用初值比对时，相邻寄存器可能恰好同值，错位不会被发现。
