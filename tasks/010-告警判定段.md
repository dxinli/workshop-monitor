# 010 告警判定段

> 计划任务：M9（复杂度 L）　状态：待办

## 要建什么

消费有界队列，做阈值求值、去抖、告警状态机、通知请求、活动集合重建。单消费者单写者，不加锁。

## 验收

- [ ] 模拟量连续 N 次越限才告警，单次波动不告警，N 按测点配置（`BR-32`）
- [ ] 恢复需**连续 N 次**不满足（不是首次未命中），与触发对称（`BR-33`）— 见「偏差」
- [ ] 开关量当次即告警、当次即恢复，不去抖（`BR-34`）
- [ ] 高高限触发时闭合同测点的高限活动告警
- [ ] 质量非 `GOOD` 不参与求值，在入口即返回（`BR-18`）
- [ ] 补传数据只记告警、不发通知（`BR-36`）
- [ ] 同测点同规则未恢复期间不重复拉响（`BR-38`）
- [ ] 判定与排序一律用 `collectTime`，不用 `receiveTime`（`BR-35`）
- [ ] 重启后活动告警集合从库重建，不重复拉响
- [ ] 阈值改后 60 秒内生效，整表原子替换不逐条更新
- [ ] 通知异步发出，adapter 内无重试；按级别决定是否通知（`BR-39`）
- [ ] 队列满时丢弃并计数，不阻塞入库
- [ ] 状态四态：`ACTIVE` / `RECOVERED` / `ACKED` / `CLOSED`（`BR-31`）
