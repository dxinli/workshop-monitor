# 任务单模板

复制下面模板为 `tasks/<编号>-<名称>.md`，编号接现有最大号往后排，填完再动手。

## 切片规则

任务必须是**垂直切片**：一条窄但完整的路径，从入口穿到存储再回到可观察结果。不是"先写所有 model、再写所有 repo"这种横向切片。

- 一条切片做完，能单独演示或验证
- 依赖关系显式写进「阻塞」，不靠顺序暗示
- 预重构先做（先让改动变容易，再做容易的改动）

反例：`019 实现 ingest 层的三个文件` —— 按层切，做完验证不了任何事
正例：`019 一条报文从订阅到落库` —— 穿过 router → codec → idem → sink，完成后能查到一行历史

## 模板

````markdown
# NNN 名称

> 计划任务：Mx（复杂度 X）　状态：待办

## 要建什么

<端到端行为。不写逐层实现步骤，不贴大段代码（会过期）>

## 验收

- [ ] <可机械验证的条目>
- [ ] <命令或查询>
- [ ] <用例编号 AC-xx>

## 阻塞

<依赖哪几份任务单；没有就写「无，可立即开始」>

## 加载

- 规则来源：<文档路径> §<节号>
- rules：<文件>

## 偏差

<与既有文档不一致处，写清依据哪条优先；没有就写「无」>
````

## 规则来源怎么写

`BR-xx` 是标签，不是路径。上面模板里「规则来源」要求的是能直接打开的文件与节，`BR-xx` 只挂在验收句末做追溯，不单独充当规则来源——只写一串编号的任务单，下一个人得先猜去哪查。

`BR-xx` 指向 `../../docs/00-需求/03-业务规则.md`。**任务单里一律写两级**：任务单在 `tasks/`，业务规则在 `docs/00-需求/`。`CLAUDE.md` 位于仓库根，同一文件在那边是 `../docs/...`，照抄进任务单会解析不到。

## 验收标准写法

不可机械验证的一律不接受：

| 不收 | 改成 |
|---|---|
| 功能正常 | `make test ./internal/adapter/...` 通过 |
| 性能良好 | AC-12：补传 500 条后 `realtime_value.collect_time` 未回退 |
| 数据不丢 | 断电 60 秒恢复后队列条数为 0，历史表新增行数 = 原队列条数 |
| 边界已处理 | 空值 / 越界 / 并发 三类各有测试，且测试在既定 seam 上 |
| 代码规范 | `make lint` 无新增问题；`grep -r "internal/agent" internal/adapter/` 为空 |

覆盖率不做统一阈值。判定类逻辑（换算、去抖、状态机）要求分支全覆盖；外部依赖密集的编排代码不设阈值，但关键分支组合必须覆盖。

## 写完之后

1. 在 `tasks/00-INDEX.md` 的表格里加一行，状态填「待办」
2. 把新任务单接进依赖图
3. 若与既有文档有冲突，写进「偏差」段并登记到 `../docs/07-待确认项与开放决策.md`（编号接现有最大值往后排）
