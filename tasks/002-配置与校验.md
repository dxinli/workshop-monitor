# 002 配置与校验

> 计划任务：M2（复杂度 S）　状态：待办

## 要建什么

5 台终端的点表配置、告警阈值、配置校验 schema，以及 `make verify-config` 与 `make seed` 两个命令。

配置文件是唯一权威源，数据库只是供界面读取的投影。

## 验收

- [x] 5 份 JSON，终端标识 `ESN-ZX-0001`~`0005`，与安装位置一一对应（`BR-01`）
- [x] 5 份合计 10 总线 / 50 从站 / 140 测点，V-10 数量断言通过
- [x] 测点标识按 `terminalId + busId + slaveAddr + pointCode` 拼装，顺序固定不得调整（`BR-05`）
- [x] 每个测点同时定义属性与告警规则，规则可为空（`BR-45`）
- [x] V-01~V-11 每条独立校验，失败输出**具体字段与原始值**，不只说"配置错误"
- [x] `make verify-config` 对合法配置返回 0，对写坏的配置返回非 0
- [x] `make seed` 生成可导入 SQL，导入后 `point` 表 140 行
- [x] 把某测点缩放系数改成 0，`make verify-config` 报 V-05 并指名该测点
- [x] 终端、总线、设备、测点、采集周期、阈值、主题命名全部可配置，不硬编码（`BR-43`）
- [x] 阈值配置覆盖 AL-01~AL-15 共 15 条规则

## 偏差

1. **任务单的 AL-01~AL-15 在文档里叫 TH-01~TH-15。** 接口规范 §11.1 的规则表用 `TH-` 前缀，
   全仓仅本任务单写 `AL-`。按文档实现为 `TH-01`~`TH-15`，`config/thresholds.json` 的 `id` 即此编号。
   术语以接口规范为准，不在配置里另造一套编号。

2. **15 条模板展开成 95 行阈值。** 模板按「终端 × 测点」展开为 `POINT` 作用域：
   15 条模板里有 13 条各挂 1 个测点、`TH-05`/`TH-06` 各挂 `ia`/`ib`/`ic` 三个，
   即每条终端 13 + 3 + 3 = 19 行，5 台终端共 **95 行**。
   模板不写 `bus_id`，展开后 `bus_id` 为 NULL，含义是该终端两条总线都适用。
   数据库设计说明书 §9 的 D-04 原写「15 条基础规则」，已同步改为 95 行并说明换算。

3. **校验器做成 Go 命令 `cmd/config-tool`，规则在 `internal/config`。** 理由见 ADR-14：
   edge-agent 启动时要做同一套校验，脚本与进程两份实现必然漂移。
   这新增了一个共享包与一个 `cmd/` 入口，`AGENTS.md` 的 Ask First 已确认。

4. **`config/topics.json` 是主题字符串的唯一来源。** 冻结线 A 的命名方案原文两套不同形
   （`internal` 写 `edge/v2/{esn}/measurement`），与 003 已验收的 ACL 冲突。
   经确认以 ACL 实现为准：两套同形、仅前缀不同（`grid` = `/edge/`，`internal` = `/workshop/`）。
   接口规范 §5.1 §5.2 已同步，`make verify-config` 会比对模板与 ACL 是否一致。

5. **点表增加 `configVersion` 顶层字段。** `terminal.config_version` 为 NOT NULL，
   而原结构里没有版本来源。语义化版本号写入库列；V-12 据此判断「是否变更」，
   没有它每次启动都会记一条配置加载事件。接口规范 §3.7 已同步。

6. **设备增加 `type` 字段。** `device.device_type` 为 NOT NULL，原结构里没有对应键。
   取英文短名（`motor_monitor` / `power_meter` / `temp_humidity_transmitter` / `safety_module` /
   `pressure_transmitter`），与测点 `code` 同一风格。

7. **测点增加 `name` 字段。** `point.point_name` 为 NOT NULL；`code` 一经使用不得改名
   （`BR-46`），展示名称必须有独立字段承载，不能拿 `code` 兼作展示。

8. **`make seed` 拆成 `seed-sql` 与 `seed` 两个目标。** `seed-sql` 只生成
   `deploy/timescaledb/init/02_seed.sql`（进仓库，供 `docker-entrypoint-initdb` 首次初始化使用），
   `seed` 只导入。合并成一个目标会导致「导入依赖生成、生成又要连库」的循环。

9. **V-10 判据按 5/10/50/140 四项分别断言。** 原文只给 `5 × 2 × 14 = 140`；
   实现里把终端、总线、从站、测点四项各自与约定值比较，任一项不符都报 V-10 并给出实际值，
   便于裁剪演示时定位是哪一层数量变了。

10. **`config/schema/` 只做形状与取值域，不重复语义规则。** 语义规则（V-03/V-05/V-06/V-07）
    需要跨字段、跨块计算，JSON Schema 表达不了；两边都写会形成第二套真相。
