# 009 终端状态三源合成

> 计划任务：M8（复杂度 M）　状态：待办

## 要建什么

由 LWT 断连通知、状态消息、数据超时三个来源合成终端在线状态，写入 `terminal_state`，状态变化记 `device_event`。

## 验收

- [x] 优先级正确：显式离线（LWT / 优雅退出）> 数据超时 > 有非补传数据即在线
- [x] 终端离线：收到异常断开通知、连续 3 个上报周期无数据、主动上报离线，任一成立（`BR-27`）
- [x] 设备离线：连续 5 次采集失败（`BR-28`）
- [x] `lastData` 只被非补传数据推进；补传不得把已超时终端刷回在线
- [x] 终端离线与设备离线是两类独立事件，分别落 `device_event`，分别展示、分别告警（`BR-29`）
- [x] 设备恢复以首次采集成功为准，产生恢复事件（`BR-30`）
- [x] 状态表每终端一行，不累积历史

## 偏差

1. **判定器 `TermState` 放在 `internal/adapter/ingest`，而不是新建包。** 规则文件把「终端状态三源合成」
   写在 `adapter-ingest.md` 里，路径前缀也是 `internal/adapter/ingest/**`；新建 `termstate` 包会让
   订阅回调与状态判定之间多一道没人强制的边界。放同包内，`Pipeline` 直接持有它。

2. **`Pipeline.WithTermState` 是可选注入。** 不注入时 008 的行为一字不变（只落库、不写 `terminal_state`），
   008 的既有测试因此不用改。需要状态合成的是 `cmd/proto-adapter`，由装配决定。

3. **状态判定在写库成功之后推进。** 若先判状态再写库，写库失败时判定器已经前移，
   QoS1 重投会看到「已经是在线/离线」，于是丢掉本应产生的事件。顺序固定为「写库 → 推进判定器」。

4. **补传数据既不动 `lastData` 也不改状态。** `ApplyData` 在 `backfill` 为真时直接返回当前状态。
   联调验证：终端已因 `DATA_TIMEOUT` 离线后发一条 `backfill=true` 的报文，状态仍是
   `OFFLINE / DATA_TIMEOUT`；随后发非补传数据才回到 `ONLINE / DATA_RECEIVED`。

5. **只有状态变化才写 `terminal_state` 与事件。** `Transition.Changed` 为假时只留原文。
   否则每 5 秒一条数据都会刷新状态表，「每终端一行」退化成流水表；联调中重复上报
   `ONLINE` 未产生第二条事件。

6. **数据驱动的状态变化单独落库。** 状态报文由 `WriteStatus` 在同一事务内更新 `terminal_state`；
   数据报文的「UNKNOWN → ONLINE」由 `Pipeline.applyData` 在事务外再写一次。写失败不回滚已入库的测量——
   状态会在下个周期或巡检时重新写出，错误记在 `Pipeline.LastStateError` 供健康检查读取。

7. **设备离线走事件驱动，不复用失败计数。** 收到 `SENSOR_OFFLINE` 事件时调 `MarkDeviceOffline` 直接置离线，
   不再累计 5 次——事件本身就代表「连续 5 次失败」已经成立，再数一遍等于同一判定做两次，
   恢复后会因计数残留立刻判离线。`DeviceFailure` 的计数路径保留给直接观测失败的调用方，两者不混用。

8. **巡检周期取 `collectIntervalMs`，新增 `config/adapter.json` 的同名字段。** 判离线窗口是 3 个周期，
   巡检比周期更密只会重复判定。终端的采集周期与 adapter 的巡检周期必须一致，否则超时判定会偏。

9. **`WriteTermState` 与 `WriteDeviceEvent` 抽成 `StateSink` 接口。** `Sink` 接口保持 008 的五个方法不变，
   状态能力用单独的小接口，`Pipeline` 在注入 `TermState` 时才做类型断言。避免所有测试桩都要实现新方法。

## 联调记录（本机，grid 方案）

| 场景 | 观测结果 |
|---|---|
| 发 `STATUS OFFLINE / UNEXPECTED_DISCONNECT` | `terminal_state` = `OFFLINE / UNEXPECTED_DISCONNECT`，记 `TERMINAL_OFFLINE` |
| 发非补传数据 | 回到 `ONLINE / DATA_RECEIVED`，`last_data_time` 取 `collectTime` |
| 停止发数据 18 秒（> 3 × 5 s） | 巡检判 `OFFLINE / DATA_TIMEOUT`，记 `TERMINAL_OFFLINE` |
| 超时后再发补传数据 | 仍 `OFFLINE / DATA_TIMEOUT`，未被刷回在线 |
| 随后发非补传数据 | 回到 `ONLINE / DATA_RECEIVED` |
| 已在线时再发 `STATUS OFFLINE` | 立刻 `OFFLINE`，显式离线压过数据新鲜度 |
| 重复上报 `ONLINE` | 状态表不重复写，事件不重复记 |
