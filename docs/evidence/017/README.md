## 通道纪律

**AC-01~03、AC-09~13、AC-16 全部走主通道**（模拟器 → 虚拟串口 → 采集应用 →
Broker → 平台），未使用旁路构造器。这些用例的证据产生于 004/005/007/016
各任务的主通道执行（见 `cross-reference.md` 逐条出处）。

AC-14/AC-17 涉及「较旧 collectTime」与「同一 msgId 重复投递」两种时序，
主通道的采集时钟无法造出这两种时序；用真实终端凭据经 Broker 注入
（走完 Broker → 平台全链路，跳过无关的串口采集段），并在证据中标明。

## 三、结论

- **20 用例全部「通过」**，无「不通过」无「阻塞」；其中 12 例归集既有主通道证据
  （004/005/007/011/012/016），8 例本次执行（含 2 例注入通道，边界已声明）。
- **MV-01~10 全部达标**。两项贴线项如实记录：MV-01 的 3036 ms 离群样本（P95 判据
  之外，C 级观察项）；MV-10 的十进制口径 3.065 GB 贴线（GiB 口径 2.854 达标）。
- **缺陷 DEF-01（B 级）已修复闭环**，回归验证落在 AC-19。
- **主通道纪律复核：是**——AC-01~03、AC-09~13、AC-16 未使用旁路构造器。

按 docs/09 的三档口径：无「不通过」用例、关键指标（MV-01/02/04/09）全部达标、
无遗留缺陷 → 具备「通过」档条件；两项贴线观察项（MV-01 离群、MV-10 口径）
移交 018 在缺陷统计中定级（建议 C 级），是否影响最终档位由 018 签署裁定。
