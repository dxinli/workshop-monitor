## 一、指标定义

### MV-01　采集到上报时延　`[引]`

| 项 | 内容 |
|---|---|
| 目标 | ≤ 2 秒 |
| 出处 | §10「时延」行：采集到上报 ≤ 2 秒 |
| 测量 | 取 `header.sendTime - header.collectTime`，采样 100 条取 P95 |
| 证据 | 时延分布表 |

### MV-02　上报到入库时延　`[引]`

| 项 | 内容 |
|---|---|
| 目标 | ≤ 3 秒 |
| 出处 | §10「时延」行：入库 ≤ 3 秒 |
| 测量 | 取 `measurement.receive_time - header.sendTime`，采样 100 条取 P95 |
| 证据 | 时延分布表 |

### MV-03　界面刷新粒度　`[引]`

| 项 | 内容 |
|---|---|
| 目标 | ≤ 5 秒 |
| 出处 | §10「时延」行：界面刷新 5 秒；§10 末注「界面刷新粒度为 5 秒」 |
| 测量 | Grafana 面板刷新间隔配置 + 连续两次取值的观测间隔 |
| 证据 | 面板 JSON 的 `refresh` 字段与实测观测 |

### MV-04　端到端时延　`[引]`

| 项 | 内容 |
|---|---|
| 目标 | ≤ 采集周期 + 10 秒 |
| 出处 | §10「时延」行 |
| 测量 | `界面呈现时刻 - collectTime`，采集周期为 5 秒时即 ≤ 15 秒 |
| 证据 | 端到端时延分布表 |

### MV-05　可观测性：健康检查与积压指标可读　`[推]`

| 项 | 内容 |
|---|---|
| 目标 | 两个自研服务的 `/healthz` 可读，含积压指标 |
| 出处 | §10「可观测性」行只写「健康检查、结构化日志、积压指标」，未给编号与目标值 |
| 测量 | `GET /healthz` 返回 `config`/`serial`/`mqtt`/`cache` 四项，`cache` 含 `depth`/`bytes`/`dropCount`；proto-adapter 含 evaluate 六字段与活动告警对账 |
| 证据 | `docs/evidence/015/acceptance.json`（7 条端到端用例） |

### MV-06　存储与保留策略　`[推]`

| 项 | 内容 |
|---|---|
| 目标 | 明细 7 天、分钟聚合 30 天；磁盘占用在 50 GB 预算内 |
| 出处 | `.claude/rules/deploy-config.md` 保留策略表；`docs/01-概要设计说明书.md` §5.2 |
| 测量 | 查 `timescaledb_information.jobs` 的 `policy_retention` 配置；造旧数据跑策略验证真清理；查库体积 |
| 证据 | `docs/evidence/016` 的保留策略用例（造 8 天前数据 → 跑策略 → 断言归零） |

### MV-07　30 天趋势查询走聚合　`[推]`

| 项 | 内容 |
|---|---|
| 目标 | 30 天趋势查询命中分钟聚合，不扫明细全表 |
| 出处 | §5.2「30 天曲线走分钟聚合而非明细」；`tasks/013` 的 8 面板验收 |
| 测量 | 30 天时间范围的查询计划（`EXPLAIN`）命中 `measurement_1m`；查询耗时可接受 |
| 证据 | 查询计划截取 + `docs/evidence/013/plan-30d.txt` |

### MV-08　通知触达率　`[推]`

| 项 | 内容 |
|---|---|
| 目标 | level 2~4 的告警 100% 写入 `notify_log`（成功或失败均有留痕，不静默） |
| 出处 | §7.2 重试策略与 `tasks/011` 验收「成功与失败都写 notify_log」 |
| 测量 | 统计 `alarm` 中 level ≥ 2 的行数 vs `notify_log` 中有对应 `notify_id` 的行数 |
| 证据 | 两侧计数对比 |

### MV-09　采集性能　`[引]`

| 项 | 内容 |
|---|---|
| 目标 | 140 测点 5 秒周期 |
| 出处 | §10「性能」行：140 测点 5 秒周期；单终端 100 测点 10 秒为配置上限 |
| 测量 | 连续 30 个采集周期，统计每周期产出测点数与周期间隔 |
| 证据 | 采集周期序列（与 AC-01 同源） |

### MV-10　轻量化　`[引]`

| 项 | 内容 |
|---|---|
| 目标 | 单机 4 核 / 8 GB；镜像总体积 ≤ 3 GB |
| 出处 | §10「轻量化」行；`.claude/rules/deploy-config.md` 首段 |
| 测量 | `docker system df` 取镜像总尺寸；运行时内存观测 |
| 证据 | 镜像尺寸表与内存观测 |

## 二、验收标准（018 的质量结论口径）

三档结论，**不合成一句「已完成」**：

| 结论 | 判据 |
|---|---|
| **通过** | 20 个用例全部「通过」；MV-01~10 全部达标；无遗留缺陷 |
| **有条件通过** | 无「不通过」项；但存在未达标指标或遗留缺陷，且已给出处理结论与责任方 |
| **不通过** | 存在「不通过」用例，或关键指标（MV-01/02/04/09）未达标 |

### 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| A | 阻断演示或数据不可信 | 必须修复后复验 |
| B | 功能缺失或口径错误 | 修复或明确降级，写入遗留问题 |
| C | 体验或文档问题 | 记录，不要求本次修复 |

### 遗留问题清单必须含

1. `docs/07-待确认项与开放决策.md` 中状态为「开放」的条目
2. 未达标指标及原因
3. 未修复的 B/C 级缺陷
