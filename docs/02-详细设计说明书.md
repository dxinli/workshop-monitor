## 2. 采集应用设计

### 2.1 启动流程

```text
1. 读取配置文件（终端点表、串口参数、上行参数）
2. 校验配置（§7.1 V-01~V-12），失败则输出错误并退出（非 0）
3. 打开串口，打不开则退出
4. 打开本地队列，读取最大序号，续接序号分配
5. 建立 MQTT 连接，注册断连通知（LWT）
6. 启动总线轮询协程（每总线一个）
7. 启动上报协程、补传协程
8. 启动健康检查 HTTP 服务
9. 等待退出信号，收到后停止采集、刷盘、断开连接
```

启动顺序有强依赖：配置校验在最前，串口在队列之前，MQTT 在协程之前。任一步失败即终止，不做降级启动——带病启动会产出难以解释的错值。

### 2.2 并发结构与共享状态

| 协程 | 数量 | 持有状态 | 与谁共享 |
|---|---|---|---|
| 总线轮询 | 每总线 1 个 | 串口句柄、本总线点表 | 序号分配器（原子） |
| 上报 | 1 | MQTT 连接 | 采集结果队列 |
| 补传 | 1 | 本地队列游标 | 本地队列锁 |
| 健康检查 | 1 | 只读快照 | 无 |

共享状态只有两处：序号分配器（原子递增）与本地队列（带锁）。总线之间不共享任何锁，一条总线阻塞不影响另一条。

### 2.3 关键算法

#### A1 采集调度

```text
func runBus(bus):
    ticker = newTicker(collectIntervalMs)
    for range ticker.C:
        batch = empty; t0 = now()
        for device in bus.devices:              # 按从站地址升序
            for block in device.blocks:         # 每从站按寄存器块请求
                resp = modbusRead(bus, device.slaveAddr, block, timeout, retry=2)
                batch += decode(block, resp)    # 失败点也进 batch，值为空
        batch.collectTime = t0                  # 取本批开始时刻
        egress.push(batch)                      # 非阻塞，不等待上报
```

三条实现约束：

1. 采集循环不等待上报结果，上行断开时采集继续；
2. 采集时间取本批开始时刻，否则同批测点时间不一致，曲线出现锯齿；
3. 总线之间只共享序号原子分配器，不共享锁。

#### A2 工程值换算与量程校验

```text
func toEngineering(raw, point):
    v = (point.width == 2) ? (raw.hi << 16) | raw.lo : raw      # 高字在前
    if point.dataType == int16 and v >= 0x8000:      v -= 0x10000
    if point.dataType == int32 and v >= 0x80000000:  v -= 0x100000000
    eng = round(v * point.scale + point.offset, decimalsOf(point.scale))
    if eng < point.min or eng > point.max:
        return {value: eng, quality: OUT_OF_RANGE}              # 保留数值
    return {value: eng, quality: GOOD}
```

超量程保留原值并标记质量，不置空——置空会丢失"值异常但可读"的信息。

#### A3 上报与出队

```text
func send(batch, backfill):
    if !mqttConnected():
        cache.append(batch); return                 # 落盘，采集继续
    token = mqtt.Publish(topic, payload, qos=1)
    if token.WaitTimeout(pubAckTimeout) != nil:
        cache.append(batch); return                 # 超时也落盘
    if backfill: cache.remove(batch.seq)            # 只有确认才出队
```

出队凭据是 Broker 确认，不是"已发出"。这是断网不丢数的唯一保障。

#### A4 补传

```text
func onReconnect():
    for {
        items = cache.peek(limit=BACKFILL_BATCH)    # 500 条一批
        if len(items) == 0: break
        for it in items:
            send(it, backfill=true)                 # 保留原采集时间，更新发送时间
        sleep(BACKFILL_INTERVAL_MS)                 # 50 毫秒批间隔
```

补传按序号正序，限速由批大小与批间隔控制，避免恢复瞬间冲击平台。补传期间采集不暂停。

#### A5 队列裁剪与丢弃事件

```text
func trim(cache):                                   # 每次入队后执行
    for limit in [RETENTION_7D, COUNT_300K, SIZE_512MB]:
        while over(limit):
            dropOldest(cache); dropped++            # 先进先出丢最旧
    if dropped >= 1000:
        publish EVENT CACHE_DROPPED {droppedCount: dropped}
        dropped = 0                                 # 不得静默丢弃
    if any(usage >= 80%):
        publish EVENT CACHE_WARNING {dimension, usagePct}   # 同级不重复上报
```

三个上限任一先到即生效。裁剪与补传共用同一把队列锁，但裁剪不得阻塞采集循环。

### 2.4 错误分类与处理

| 错误类型 | 判定依据 | 数据质量 | 处理 |
|---|---|---|---|
| 通信超时 | 响应超时 | 通信失败 | 重试 2 次，仍失败记本点失败 |
| 设备异常应答 | 响应含异常码 | 设备异常 | 不重试，直接标记 |
| 校验错误 | CRC 不匹配 | 校验错误 | 重试 1 次，仍失败标记 |
| 解析失败 | 帧长度或字段越界 | 解析失败 | 标记，记录原始帧 |
| 超量程 | 工程值越界 | 超量程 | 保留数值并标记 |

任何失败都不沿用上一次正常值。值为空时上报空值，质量码如实标记。

## 3. 接入服务设计

### 3.1 启动流程

```text
1. 读取配置（数据库连接、订阅参数、主题模板、通知端点）
2. 连接数据库，校验表结构存在
3. 载入阈值到内存快照
4. 从数据库重建活动告警集合
5. 建立 MQTT 订阅（持久会话，清理会话关闭）
6. 启动判定协程
7. 启动状态巡检协程
8. 启动健康检查 HTTP 服务
9. 启动阈值热加载协程（每 60 秒）
```

活动告警集合必须在订阅之前重建完成，否则订阅后立即到达的数据可能对已告警测点重复拉响。

### 3.2 接收段处理链

```text
① 主题解析    按模板提取终端标识与消息类型
② 报文解码    Codec 按配置选择（客户规范 / 内部标准）
③ 归一化      四遥类型、单位、质量码、三时间
④ 幂等判定    终端标识 + 序号
⑤ 原始报文留存 不论解析成功与否
⑥ 投影        历史测量、实时值、终端状态
⑦ 投递判定   入库成功后推入有界 channel
```

#### A6 幂等判定

```text
func ingest(msg):
    ok = INSERT INTO message_log(...) ON CONFLICT (terminal_id, seq) DO NOTHING
    if !ok:
        metrics.duplicate++
        return DUPLICATE                            # 不写历史、实时值、事件
    BEGIN TX
        raw_message.insert(...)                     # 原文留存
        if msg.parseStatus != OK: COMMIT; return    # 解析失败只留原文
        measurement.bulkInsert(rows)                # 单事务批量
        upsertRealtime(rows)                        # A7
        updateTerminalState(...)                    # A9
    COMMIT
    publishToEvaluate(rows)                         # 事务外投递
```

幂等判定必须在写任何业务表之前。先写后去重会产生脏数据，且删除脏数据会影响已聚合的分钟视图。

#### A7 实时值合并

```text
INSERT INTO realtime_value(...) VALUES(...)
ON CONFLICT (terminal_id, point_id) DO UPDATE
SET value = EXCLUDED.value, quality = EXCLUDED.quality,
    collect_time = EXCLUDED.collect_time, seq = EXCLUDED.seq, updated_at = now()
WHERE EXCLUDED.collect_time > realtime_value.collect_time
   OR (EXCLUDED.collect_time = realtime_value.collect_time
       AND EXCLUDED.seq > realtime_value.seq);
```

调用前已过滤补传行，补传旧数据不进实时值通道。

#### A8 终端状态三源合成

```text
优先级：显式离线（断连通知 / 优雅退出）> 数据超时 > 有非补传数据即在线

func onStatus(msg):
    msg.status == OFFLINE ? setState(OFFLINE, reason) : setState(ONLINE, CONNECTED)

func onData(msg):
    lastData = msg.collectTime
    setState(ONLINE, DATA_RECEIVED)

巡检（每周期）：
    if state == ONLINE and now - lastData > TERMINAL_OFFLINE_PERIODS * interval:
        setState(OFFLINE, DATA_TIMEOUT)
```

`lastData` 只按非补传数据推进。补传数据不得把已超时的终端刷回在线。

### 3.3 判定段实现

#### A9 去抖与告警合并

单消费者协程，状态单写者，不加锁。

```text
# 接收侧：入库成功后投递，绝不等待
func afterCommit(record):
    select {
    case queue <- record:                       # 有界 channel，容量 4096
    default:
        metrics.dropCount++                     # 满则丢弃并计数
        log.warn("evaluate queue full, point=%s", record.pointId)
    }

# 判定侧：单协程串行消费
func consume():
    for e := range queue:
        evaluate(e)

func evaluate(e):
    if e.quality != GOOD: return                # 坏点不参与求值
    ths := snapshot.thresholdsFor(e.pointId)    # 原子快照，测点 > 总线 > 全局
    for th in ths:
        hit := compare(e.value, th.operator, th.threshold_value)
        key := e.terminalId + "|" + e.pointId + "|" + th.alarmType

        if th.debounceCount == 0:               # 开关量：不去抖
            hit ? raise(key, e, th) : clear(key, e)
            continue

        n := counters[key]
        if hit { n++ } else { n = 0 }
        counters[key] = n

        if hit && n == th.debounceCount && !active.contains(key):
            raise(key, e, th)
        if !hit && n == 0 && active.contains(key):
            clear(key, e)

func raise(key, e, th):
    closeLowerSamePoint(key)                    # 高高限闭合高限
    UPSERT alarm ON CONFLICT(dedupe_key) WHERE status='ACTIVE'
        DO UPDATE SET last_time=..., trigger_value=..., trigger_count=trigger_count+1
    active.add(key)
    if !e.backfill:                             # 补传不通知
        notifyId = "NT-" + e.terminalId + "-" + e.pointId + "-" + e.occurTime
        go postNotify(notifyId, e, th)          # 异步，失败只记投递日志

func clear(key, e):
    UPDATE alarm SET recover_time=..., status='RECOVERED'
        WHERE dedupe_key=... AND status='ACTIVE'
    active.remove(key)
    counters[key] = 0

func bootstrap():
    for row in SELECT dedupe_key FROM alarm WHERE status='ACTIVE':
        active.add(row.dedupe_key)              # 必须重建
    # counters 保持空，去抖计数从 0 开始
```

**三条实现约束**

| 约束 | 原因 |
|---|---|
| 消费者必须唯一 | 多消费者会让计数与活动集合变成多写者，必须加锁，且顺序错乱会让去抖计数跳跃 |
| 通知必须异步 | 同步调用会把投递响应时间计入判定耗时，导致队列积压 |
| 阈值快照原子替换 | 就地更新会出现"半个周期用旧规则"，瞬态误判最难排查 |

### 3.4 阈值热加载

```text
func reloadLoop():
    for range ticker.every(60s):
        newSnapshot = loadThresholdsFromDB()
        atomic.StorePointer(&snapshot, newSnapshot)     # 只换指针
```

判定协程始终持有某个完整快照，重载只替换指针。逐条就地更新会导致同一次求值中读到新旧混杂的规则。

### 3.5 错误处理

| 场景 | 处理 | 是否影响其他链路 |
|---|---|---|
| 报文解析失败 | 留原始报文 + 失败原因，不写历史 | 否 |
| 数据库写入失败 | 重试 3 次（立即 / 1 秒 / 5 秒），仍失败记服务健康异常 | 判定侧不受影响 |
| 判定队列满 | 丢弃并计数，记服务健康 | 入库不受影响 |
| 通知请求失败 | 记投递日志，不回滚告警 | 告警记录完整 |
| 幂等冲突 | 计数重复，直接返回 | 否 |
| 活动集合与数据库不一致 | 健康检查报异常，需重启 | 重启后重建 |

## 4. 通知接口实现

### 4.1 请求字段

`POST {NOTIFY_ENDPOINT}`，由 Node-RED 接收。

| 字段 | 类型 | 必填 | 说明 |
|---|---|:--:|---|
| `notifyId` | string | ✓ | `NT-{terminalId}-{pointId}-{occurTime}` |
| `terminalId` | string | ✓ | 终端标识 |
| `pointId` | string | ✓ | 测点标识 |
| `alarmType` | string | ✓ | 告警类型枚举 |
| `level` | int | ✓ | 1~4 |
| `triggerValue` | number | ✓ | 触发值（工程值） |
| `occurTime` | int64 | ✓ | 毫秒，采集时间轴 |
| `scene` | string | | 告警发生时的工况场景 |
| `reason` | string | | 人类可读原因 |

### 4.2 约定

1. 请求不含认证头，只在内网直调，编排层不暴露公网；
2. 接入服务只发不等结果，短超时，失败只记投递日志；
3. 投递失败的重试责任在编排层，接入服务不做重试；
4. 编排层完全不可达时，接入服务记一条失败记录并继续，不回滚告警落库；
5. `notifyId` 由接入服务生成，编排层不得重新生成，避免两侧不一致导致去重失效。

### 4.3 编排层流程

| 流程 | 入口 | 职责 | 关键节点 |
|---|---|---|---|
| N-01 通知接收 | `POST /api/notify` | 校验入参、按级别分流、组装卡片 | http in → function → switch |
| N-02 投递与重试 | N-01 输出 | HTTP 投递、1/5/15 秒重试、写投递日志 | http request → delay → catch → postgres |
| N-03 告警确认 | `POST /api/ack` + 面板 | 写确认记录、更新告警状态 | http in → postgres |
| N-04 演示面板 | 写视图 | 场景切换、健康查看、跳转读视图 | ui_button → http request |

### 4.4 错误分支

| 错误 | 捕获点 | 处理 |
|---|---|---|
| 请求 JSON 解析失败 | N-01 catch | 返回 400，不写库（无可用通知标识） |
| 必填字段缺失 | N-01 function | 返回 422，不写库 |
| 投递 HTTP 失败 | N-02 catch | 按 1/5/15 秒重试，末端写失败记录 |
| 数据库写失败 | N-02 / N-03 catch | 重试 3 次，仍失败写服务健康异常 |

参数校验失败时不写投递日志——没有可信的通知标识做主键，强行写会产生无主记录或无意义冲突。这类错误属调用方缺陷，应在接入服务日志暴露。

编排层的失败不回传到接入服务。接入服务只发不等结果，投递失败信息由投递日志承载，不在请求响应中体现。

### 4.5 无状态设计

编排层不承载任何跨消息状态，不配置上下文持久化。去抖计数与活动告警集合都在接入服务内存中，编排层只做管道。

## 5. 健康检查

`GET /healthz` → `200`（就绪或降级）/ `503`（不可用）

```json
{
  "status": "degraded",
  "service": "edge-agent",
  "instance": "ESN-ZX-0001",
  "version": "1.0.0",
  "uptimeSec": 3600,
  "checks": {
    "config": {"status": "ok", "configVersion": "1.0.0"},
    "serial": {"status": "ok", "buses": {"A": "open", "B": "open"}},
    "mqtt":   {"status": "degraded", "connected": false, "lastSuccess": 1793500200230},
    "cache":  {"status": "ok", "depth": 0, "bytes": 0, "dropCount": 0}
  }
}
```

| 判据 | 结论 |
|---|---|
| MQTT 断开但采集正常 | 降级，HTTP 200。断网是设计内状态，返回 503 会被编排重启容器，打断采集并丢缓存 |
| 串口任一总线打不开 | 不可用，HTTP 503 |
| 缓存达 80% | 降级，与缓存预警事件同源 |

接入服务追加判定段字段：

```json
{
  "evaluate": {
    "queueDepth": 0,
    "queueCapacity": 4096,
    "dropCount": 0,
    "activeAlarmCount": 3,
    "debounceKeys": 12,
    "lastEvalTime": 1793500200123
  }
}
```

| 判据 | 结论 |
|---|---|
| 丢弃计数持续增长 | 降级。判定跟不上入库速率，告警会漏，需查阈值配置量或判定耗时 |
| 活动告警数与数据库未恢复告警数不一致 | 启动重建失败或中途异常，需重启 |
| 判定段整体缺失 | 判定协程未启动，属启动自检失败，直接 503 |
| 通知请求失败 | 不影响健康结论，只落投递日志 |

## 6. 配置规范

### 6.1 文件布局与权威源

| 配置 | 文件 | 权威源 | 入库方式 | 生效方式 |
|---|---|---|---|---|
| 终端与点表 | `config/terminals/ESN-ZX-000N.json` | 文件 | `make seed-sql` 生成、`make seed` 导入 | 采集应用启动读取；库表供界面查询 |
| 告警阈值 | `config/thresholds.json` | 文件 | 同上 | 接入服务启动载入内存；改后 60 秒内生效 |
| 主题模板 | `config/topics.json` | 文件 | 不入库 | 采集应用与接入服务启动读取 |
| 工况预设 | `config/scenes.json` | 文件 | 不入库 | 模拟器启动读取 |
| 校验 schema | `config/schema/*.schema.json` | 文件 | 不入库 | 编辑期与 CI；`cmd/config-tool` 做语义校验 |

单一权威源是配置文件，数据库是供界面与编排读取的投影。两者不一致时以文件为准并重新执行种子生成。

阈值文件里的规则是**模板**：一条规则可挂多个 `pointCodes`（如 `ia`/`ib`/`ic` 共用一条高限），
`make seed-sql` 按「终端 × 测点」展开成 `threshold` 表行，作用域一律为 `POINT`。
模板不写终端时适用全部终端；写 `terminalId` / `busId` 即为单点覆盖。

配置校验与种子生成由 `cmd/config-tool` 承担：`make verify-config` 逐条执行 V-01~V-11 并断言
失败输出含具体字段与原始值；`make seed-sql` 先校验再生成 `deploy/timescaledb/init/02_seed.sql`，`make seed` 只负责导入。
两者共用 `internal/config`，同一份规则不会出现脚本与进程两套实现。

### 6.2 校验规则

| 编号 | 规则 | 失败后果 |
|---|---|---|
| V-01 | 必填字段齐备 | 拒绝启动 |
| V-02 | 从站地址在 1~247 且总线内唯一 | 拒绝启动 |
| V-03 | 测点编码设备内唯一，匹配 `^[a-z][a-z0-9_]{1,31}$` | 拒绝启动 |
| V-04 | 数据类型与寄存器宽度匹配 | 拒绝启动 |
| V-05 | 缩放系数非零且量程下限小于上限 | 拒绝启动 |
| V-06 | 块内 `地址 + 宽度` 不重叠且不越界 | 拒绝启动 |
| V-07 | 寄存器块覆盖全部测点，无孤立点 | 拒绝启动 |
| V-08 | 四遥类型属遥测或遥信 | 拒绝启动 |
| V-09 | 单从站寄存器数不超过 125 | 拒绝启动 |
| V-10 | 5 终端 × 2 总线 × 14 测点 = 140 | 告警但不拒绝（便于裁剪演示） |
| V-11 | 阈值类型属枚举、级别在 1~4 | 拒绝启动 |
| V-12 | 配置版本变更时记一条配置加载事件 | 仅记录 |

**V-06 与 V-07 的边界**：V-06 管「不许重叠、不许越界」，V-07 管「不许有洞」。
块内测点必须从偏移 0 起连续铺满 `registerCount`，否则请求回来的寄存器里有一段没人认领，
这段值既不入库也无从判断对错。嵌套结构下不存在"块外孤立点"，V-07 校验的是它的等价形式：每个被读取的寄存器都归属于某个测点。

**V-10 只告警不拒绝**：裁剪规模（1 终端 / 1 总线 / 14 测点）是演示用的合法形态，
数量不符不能挡住启动；但默认规模的数量断言要能被 CI 与部署自检看见。

### 6.3 生效边界

| 变更类型 | 生效方式 | 需重启 |
|---|---|---|
| 阈值数值或级别 | 每 60 秒重载到内存，原子替换 | 否 |
| 工况预设 | 下次场景切换时读取 | 否 |
| 点表地址、数量、字节序 | 重启对应终端容器 | 是 |
| 串口参数 | 重启 | 是 |
| 主题命名方案 | 重启采集应用与接入服务 | 是 |

只对纯数值类配置做热加载。点表热加载会出现"半个周期用旧块、半个周期用新块"的错值，这类问题在验收现场最难解释，因此要求重启。

## 7. 日志规范

### 7.1 格式

结构化 JSON 单行输出，字段固定：

| 字段 | 类型 | 说明 |
|---|---|---|
| `ts` | int64 | 毫秒时间戳 |
| `level` | string | `debug` / `info` / `warn` / `error` |
| `svc` | string | 服务名 |
| `inst` | string | 实例标识（终端序列号或 `adapter`） |
| `msg` | string | 人类可读描述 |
| `esn` | string | 终端标识，涉及时携带 |
| `pointId` | string | 测点标识，涉及时携带 |
| `seq` | int64 | 消息序号，涉及时携带 |

### 7.2 必记事件

| 事件 | 级别 | 关键字段 |
|---|---|---|
| 启动完成 | info | 配置版本、订阅主题数 |
| 配置校验失败 | error | 规则编号、失败字段、原始值 |
| 串口打开失败 | error | 总线、端口、错误 |
| MQTT 断开 / 恢复 | warn / info | 断开原因、断开时长 |
| 队列丢弃 | warn | 丢弃计数、队列深度 |
| 幂等命中 | debug | 终端、序号 |
| 告警发生 / 恢复 | info | 去重键、级别、触发值 |
| 通知请求失败 | warn | 通知标识、失败原因 |
| 判定队列满 | warn | 队列深度、丢弃累计 |

### 7.3 禁止事项

- 不打印完整报文内容（体积大且含现场数据），只打印长度与解析状态；
- 不打印数据库连接串与口令；
- 不在循环内打印每点采集成功日志（140 点 × 5 秒会淹没日志），改为周期聚合统计。

## 8. 关键易错点

| 编号 | 易错点 | 正确做法 |
|---|---|---|
| E-01 | 上行断开时把采集循环也切到等待状态 | 采集与上报两个循环互不等待 |
| E-02 | 同批测点各自取时间 | 取本批开始时刻作为统一采集时间 |
| E-03 | 采集失败沿用上一次正常值 | 值为空并标记质量 |
| E-04 | 先写库后去重 | 幂等判定在写业务表之前 |
| E-05 | 补传数据覆盖实时值 | 实时值只接受更晚采集时间 |
| E-06 | 判定与入库同步 | 判定经有界队列异步，入库不等待 |
| E-07 | 去抖计数持久化 | 不持久化，从 0 开始；活动告警集合必须重建 |
| E-08 | 用时间差判断补传 | 用报文中的补传标记判断 |
| E-09 | 阈值逐条就地更新 | 整表快照原子替换 |
| E-10 | 累计量求和 | 电能取窗口内末值差，功率取均值 |
| E-11 | 告警重复堆叠 | 同一去重键只保留一条活动告警，恢复后闭合 |
| E-12 | 通知同步调用 | 异步发出，失败只记投递日志 |
| E-13 | 编排层承载业务判定 | 编排层只做投递管道 |
| E-14 | 面板在界面改完不导出 | 面板 JSON 纳管并版本比对 |
| E-15 | 视图内写时间过滤条件 | 时间条件由面板传入，否则无法分区裁剪 |
| E-16 | 缓存静默丢弃 | 丢弃计数并每满 1000 条上报事件 |
