## 1. 用法

**按序号从 0 到 9 启动，上游不就绪不启下游。** 每个组件固定三项：

1. **启动前配置段** —— 起它之前必须就位的配置文件段、环境变量、生成物
2. **启动命令** —— 可直接复制执行
3. **目录位置** —— 自研件给源码目录；非源码件给配置目录并在链路中的位置（L 层 / K 链路 / F 数据流）

启动后**看得见结果**的读数不在本清单展开，见 [部署验证手册](12-部署验证手册.md) §2 的六个观测面。

两个形态要分清：

- **交付件**：`edge-agent`、`proto-adapter`（Go，进交付）；其余开源组件锁版本复用
- **仿真件**：从站模拟器、wecom-mock、虚拟串口（验证手段，不进交付镜像；真实现场对应物理设备与真实通道）

## 2. 依赖与启动顺序

```text
                         ┌────────────────────────────────────────────┐
  .env（口令/地址）──────┤                                            │
    │                    │                                            │
    ├─ make passwd ──→ deploy/mosquitto/passwd ──→ ② Mosquitto ──→ ⑧ proto-adapter ──┐
    │                                              ↑ 订阅           ↑ 写库/通知       │
    └─ make seed-sql ──→ 02_seed.sql ──→ ① TimescaleDB ─────────────┘                 │
                                         ├────────→ ④ Node-RED ──→ ③ wecom-mock       │
                                         └────────→ ⑤ Grafana                         │
                                                                                      │
  ⑥ make sim-pty ──→ .pty/ 两端点表 ──┬─→ ⑦ 从站模拟器 ──→ ⑨ edge-agent ×5 ──→ ② ──┘
                                      └────────────────────→ ⑨（agent 端点）
```

| 序 | 组件 | 启动前置 | 下游 | 链路位置 |
|---:|---|---|---|---|
| 0 | 基线生成物（`.env` / 口令文件 / 种子 SQL） | — | 全部 | K7 配置装载的输入 |
| 1 | TimescaleDB | 0 | ④ ⑤ ⑧ | L4 存储 |
| 2 | Mosquitto | 0 | ⑧ ⑨ | L2 传输 |
| 3 | wecom-mock（仿真） | — | 被 ④ 投递 | L6 通知仿真 |
| 4 | Node-RED | 1 ③ | Dashboard / 库留痕 | L5 触达 + L7 写视图 |
| 5 | Grafana | 1 | 界面 | L7 读视图 |
| 6 | 虚拟串口 socat（仿真） | — | ⑦ ⑨ | L0 仿真替代 |
| 7 | 从站模拟器（仿真） | 6 | ⑨ | L0 仿真替代 |
| 8 | proto-adapter | 1 ② | ① ④ | L3 接入适配 |
| 9 | edge-agent × 5 | ② 6 7 | ② | L1 边缘采集 |

> `make up` 一条命令起齐 1+2+4+5（core 四容器，含依赖与口令文件生成）；
> ③ ⑥ ⑦ ⑧ ⑨ 不在 core 里，按本清单单独起。
> ⑧ 与 ⑨ 互不依赖：先起 ⑧ 不会漏数据（adapter 订阅是持久会话），按清单顺序只是便于分段观测。

## 3. 逐组件启动清单

### 0. 基线生成物（无常驻进程）

| 项 | 内容 |
|---|---|
| 链路位置 | K7 配置装载链路的输入端；所有组件的共同前置 |
| 目录位置 | 不是组件。产物两件：`deploy/mosquitto/passwd`（口令文件，**不入版本库**）、`deploy/timescaledb/init/02_seed.sql`（种子 SQL，入版本库） |

**启动前配置段**

| 来源 | 段 / 键 | 用途 |
|---|---|---|
| `.env`（`cp .env.example .env` 后填写） | `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | 库超级用户 |
| | `WORKSHOP_ADAPTER_PASSWORD` / `WORKSHOP_DASHBOARD_PASSWORD` / `WORKSHOP_NOTIFY_PASSWORD` / `WORKSHOP_READONLY_PASSWORD` | 四个业务角色 |
| | `MQTT_BROKER_URL` / `MQTT_TOPIC_SCHEME` | agent 与 adapter 的连接与命名方案 |
| | `MQTT_ESN_ZX_0001_PASSWORD` ~ `MQTT_ESN_ZX_0005_PASSWORD`、`MQTT_WORKSHOP_ADAPTER_PASSWORD` | 6 个 MQTT 账号口令 |
| | `NOTIFY_CHANNEL` / `WECOM_WEBHOOK_URL` / `WECOM_ENABLED` / `SIM_URL` / `GRAFANA_URL` | 通知与跳转 |
| `deploy/versions.env` | 全部 `*_VERSION` | 镜像标签唯一来源 |
| `deploy/mosquitto/acl.grid` 或 `acl.internal` | `user` 行 | 账号清单唯一来源 |
| `config/` | `terminals/` · `thresholds.json` · `topics.json` · `scenes.json` · `adapter.json` · `schema/` | 种子与各组件配置的权威源 |

**启动命令**

```bash
cp .env.example .env      # 首次；逐键填写口令
make passwd               # .env + ACL → deploy/mosquitto/passwd
make seed-sql             # config/ → deploy/timescaledb/init/02_seed.sql（先生成后起库）
```

**注意**：`02_seed.sql` 必须在 TimescaleDB **首次启动前**生成——`init/` 目录只在库初始化时执行一次。
改过 `config/` 后要 `make seed-sql && make seed` 重新投影。

### 1. TimescaleDB（非源码）

| 项 | 内容 |
|---|---|
| 链路位置 | **L4 数据存储层**。上游：⑧ 的 K4 接收落库、K5 告警写、K6 状态写；下游：④ 写投递日志、⑤ K8 只读 8 面板与写视图。落点是 F1 后段与 F3/F4/F7 的存取面 |

|---|---|
| `.env` | `POSTGRES_DB` `POSTGRES_USER` `POSTGRES_PASSWORD`；`WORKSHOP_ADAPTER_PASSWORD` `WORKSHOP_DASHBOARD_PASSWORD` `WORKSHOP_NOTIFY_PASSWORD` `WORKSHOP_READONLY_PASSWORD`（`01_schema.sql` 经 `\getenv` 读取建角色，不落明文） |

### 2. Mosquitto（非源码）

| 项 | 内容 |
|---|---|
| 链路位置 | **L2 消息传输层**。上游：⑨ 的 K2 上行发布与 K3 补传、状态报文与 LWT；下游：⑧ 的 K4 订阅接收、K6 三源之一。Broker 本身只做认证授权与分发，**不做业务判定** |
| 目录位置 | 非源码（`eclipse-mosquitto`）。配置在 `deploy/mosquitto/`：`mosquitto.conf` · `acl.grid` / `acl.internal` · `entrypoint.sh`；生成物 `passwd` 不入版本库 |

**启动前配置段**

| 来源 | 段 / 键 |
|---|---|
| `.env` | 6 个 `MQTT_*_PASSWORD`（账号名推导变量名：`ESN-ZX-0001` → `MQTT_ESN_ZX_0001_PASSWORD`）；`MQTT_TOPIC_SCHEME`（`grid` / `internal`，选中哪套 ACL） |
| `deploy/versions.env` | `MOSQUITTO_VERSION=2.0.20` |
| `deploy/mosquitto/mosquitto.conf` | `listener 1883`、`allow_anonymous false`、`password_file`、`acl_file`、持久会话与 QoS 1 离线上限（10000 条） |
| `deploy/mosquitto/acl.<scheme>` | 账号与发布 / 订阅权限（**账号清单唯一来源**，与 `config/topics.json` 逐条一致，`make verify-config` 比对） |
| 生成物 | `deploy/mosquitto/passwd` ← `make passwd`（`make up` 会自动先跑） |

**启动命令**

```bash
make passwd && make up                                         # 或单起 mosquitto 服务
docker compose -f deploy/docker-compose.yml --env-file deploy/versions.env --env-file .env up -d mosquitto
```

**注意**：ACL 与口令变更需重建该容器，不支持热生效；不要把 ACL 文件直接挂到 `/mosquitto/acl`
（挂载与属主问题见 `.claude/rules/deploy-config.md`），由 `entrypoint.sh` 按 `MQTT_TOPIC_SCHEME` 复制。

### 8. proto-adapter（自研交付件）

| 项 | 内容 |
|---|---|
| 链路位置 | **L3 接入适配层**，一进程三段：K4 接收落库、K5 告警判定与触达、K6 终端状态合成。上游：② 订阅 `prefix/+/+/up`；下游：① 写测量 / 告警 / 状态、④ 的 `POST /api/notify` |
| 目录位置 | **源码**：`cmd/proto-adapter/`（入口：参数解析 + 装配，不含业务逻辑）· `internal/adapter/ingest|evaluate|state|health` · 跨侧共享 `internal/model` `internal/pkglog` |

**启动前配置段**

| 来源 | 段 / 键 |
|---|---|
| `config/adapter.json` | `brokerUrl` · `topicScheme` · `qos` · `clientId` · `username` · `topicsFile` · `database.url`（**不带口令**）· `queue.capacity`（有界 channel） |
| `config/topics.json` | 主题模板唯一来源（`-config` 同目录引用，两套方案仅前缀不同） |
| 阈值 | **不从文件读**：从库 `monitor.threshold` 每 60 秒原子替换 ← 必须先 `make seed`，否则无规则可判 |
| 环境变量 | `MQTT_WORKSHOP_ADAPTER_PASSWORD`（订阅口令，`requireEnv` 缺了拒绝启动）· `PGPASSWORD`（**取 `WORKSHOP_ADAPTER_PASSWORD`**：`database.url` 不带口令，pgx 从 `PGPASSWORD` 补）· 可选 `HEALTH_ADDR`（默认 `127.0.0.1:9200`） |
| 前置 | ① 已 seed、② 在跑 |

**启动命令**

```bash
make build          # 先产出 bin/proto-adapter
make run-adapter    # 前台运行，Ctrl-C 停
```

`.env` 导入、`PGPASSWORD` 设置与二进制路径都收在 `scripts/start-adapter.sh` 里，
命令行不再出现口令。

**起来即验**：`curl -s http://127.0.0.1:9200/healthz`，`checks.{mqtt,ingest,evaluate}` 齐全。

### 9. edge-agent × 5（自研交付件）

| 项 | 内容 |
|---|---|
| 链路位置 | **L1 边缘采集层**，一进程三段：K1 采集换算、K2 上行发布、K3 缓存补传。上游：⑦ 寄存器（或现场传感器）；下游：② 的数据 / 事件 / 状态三类主题 |
| 目录位置 | **源码**：`cmd/edge-agent/`（入口：参数解析 + 装配）· `internal/agent/`（poller · modbus · codec · publisher · cache · backfill · health 等）· 跨侧共享 `internal/model` `internal/pkglog` `internal/config` |

**启动前配置段**

| 来源 | 段 / 键 |
|---|---|
| `config/terminals/ESN-ZX-000N.json` | 点表：总线参数（`port` / `baudRate` / `timeoutMs` / `retryCount`）、从站、寄存器块、`dataType` / `byteOrder` / `scale` / `offset` / 量程。**启动读取，改动须重启** |
| `config/topics.json` | `-topics` 默认 `config/topics.json`（主题字符串不落代码） |
| 环境变量 | `MQTT_BROKER_URL`（缺了拒绝启动）· `MQTT_ESN_ZX_000N_PASSWORD`（口令变量名按终端推导）· 可选 `MQTT_TOPIC_SCHEME`（默认 grid）· `MQTT_QOS` `MQTT_KEEPALIVE` `HEALTH_ADDR`（默认 `127.0.0.1:9101`，5 台同机逐个覆盖 9102~9105） |
| 命令行 | `-ports .pty/agent-ports.json`（**仿真形态**；真实部署不传，按点表 `port` 打开）· `-seq var/seq.state`（序号高水位，重启续接不归零）· `-cache var/cache.db`（本地持久队列，空串=不落盘） |
| 运行时目录 | `var/` 须可写（队列与序号落盘） |
| 前置 | ② 在跑；仿真形态还要 ⑥ ⑦ 就绪 |

**启动命令**（一次起 5 台，仅配置与健康口不同）

```bash
make build          # 先产出 bin/edge-agent
make sim-pty        # 仿真形态需要 .pty/agent-ports.json
make run-agents     # 一次起 5 台，前台等待，Ctrl-C 全停
```

`scripts/start-agents.sh` 按 ESN-ZX-0001~0005 逐台设 `HEALTH_ADDR` 9101~9105，
统一带 `-ports .pty/agent-ports.json`，并备好 `var/`。

**起来即验**：`curl -s http://127.0.0.1:9101/healthz`（~9105），`checks.{config,serial,mqtt,cache}` 齐全。

## 4. 停机顺序（反向）

```text
⑨ edge-agent → ⑧ proto-adapter → ⑦ 模拟器 / ⑥ 虚拟串口 → ⑤ Grafana / ④ Node-RED → ③ wecom-mock → ② Mosquitto → ① TimescaleDB
make down      # 一次停 core 四容器
```

先停采集与判定再停 Broker：反过来会让 ⑨ 在 Broker 消失瞬间积压、误触发离线判定与补传逻辑，停机日志里全是误报。
